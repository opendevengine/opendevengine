Documentation / Models and providers

Models and providers

Choose models by role. A chat provider and an execution profile serve different purposes.

Supported providers

Ollama
Chat and embedding models on this computer or another machine you own, with automatic discovery.
OpenAI-compatible endpoints
Local servers such as LM Studio, vLLM or llama.cpp, and hosted APIs with compatible capabilities.
Claude Code CLI
Chat for answers, plans and summaries using your own subscription login. No embeddings.

Assign roles

In Settings → Models, create a profile, configure its endpoint and model, test the connection, then assign it to answering, planning, repository summaries or embeddings. Chat roles require a chat-capable profile. Embeddings require an embedding-capable Ollama or OpenAI-compatible profile. Connection tests use synthetic content, not repository source.

Starting with an existing downloaded Ollama model:

opendevengine --model llama3.1:8b --data-dir ./workspace-data

--model seeds only unassigned Ask and planning roles; it does not overwrite existing assignments or select the coding agent’s model. Ollama is expected at http://127.0.0.1:11434; change it with --ollama-url.

Ollama on another machine

To use Ollama on another computer you control, such as a GPU machine on your Tailscale network or LAN, give its address:

opendevengine --ollama-url http://100.64.0.2:11434 --model llama3.1:8b --data-dir ./workspace-data

That one IP address is then treated as local: plain http is allowed to it, discovery lists its models, and it stays usable while Keep everything on this computer is on, so repository source is sent to it. Only set it for a machine you trust as much as this one, and reach it over a private network; Ollama has no login of its own. The address must be a private-network IP (LAN, or a VPN such as Tailscale), not a host name or public IP, so DNS cannot redirect it and plain http never crosses the internet. Removing the setting makes saved profiles for that address remote again: local-only mode blocks them, and their plain-http endpoints are refused even with local-only mode off.

On the Ollama machine, make Ollama listen on that address (for example OLLAMA_HOST=100.64.0.2:11434) rather than on every interface.

Enable remote inference deliberately

Keep everything on this computer is on by default. Remote providers require turning it off and explicitly allowing the profile to receive source. Remote embeddings also transmit source. Credentials go into the OS vault. Local storage alone does not imply local inference.

Timeouts and local hardware

Provider profiles default to a 60-second timeout; the local Ollama profile created by --model uses 600 seconds (10 minutes). Profile timeouts are adjustable from 1 to 600 seconds. Large local models can take minutes on a CPU; plans need longer structured output than short answers.

Use a smaller downloaded model or GPU-backed hardware if necessary. ollama ps shows CPU/GPU use. Hosted inference is another option after source-sharing consent. Unknown pricing must not be treated as zero cost.

For Docker images, agent limits and the optional Claude execution model, see execution profiles.
