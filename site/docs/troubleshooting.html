Documentation / Troubleshooting

Troubleshooting

Use the reported state to decide what to retry. Do not treat missing checks as passed.

GitHub or credentials are unavailable

Restart with --data-dir, unlock your OS keychain or vault and retry setup. Install the full optional dependencies from the setup instructions. If secure storage is missing or locked, credential setup is blocked; a plaintext key file is not a fallback.

Indexing paused: disk limit

A paused run shows disk limit when it reaches the default 4 GiB index size cap or indexing would leave less than 1 GB free on the data volume. The cap counts live database pages, so deleting a local index frees headroom. On Repositories, free disk space or use Delete local index on repositories you no longer need, then Resume.

“Choose a repository to continue”

Name the repository in your question, attach it with +, or pick a suggestion. Reasons show matching terms. Confirm Use in Ask is enabled and the index has usable source.

Answers or plans time out

Check the assigned role in Settings → Models, the profile timeout and whether the model is available. Local CPU inference can take several minutes. Run ollama ps to inspect CPU/GPU use. Try a smaller model, a longer allowed timeout or an explicitly approved hosted provider. The CLI-created Ollama profile has a 10-minute timeout; other profiles default to 60 seconds.

A session fails before the agent starts

Confirm Docker is running, the selected image is already local, Claude Code is installed and logged in, and Test execution profile passes. Check source-sharing consent, both repository switches, the plan’s execution profile and its blocking questions. Network-dependent installs need dependencies baked into the image.

The base branch changed

Inspect the freshness notice. Regenerate the plan for current source, or explicitly retain its saved base. A later publication can still be blocked by conflicting changes.

The app stopped during a session

Restart using the same data directory. Recovery confirms containment before marking work interrupted. Inspect the last checkpoint and use Retry as a new attempt. Uncheckpointed edits may be lost. A containment failure remains unresolved until the old runtime is confirmed stopped.

Publication is blocked or uncertain

Review permissions, excluded paths, sensitive-content errors, artifact availability and base divergence. When a response was lost, use Retry so the app reconciles with GitHub. Do not start a new session just to retry the same publication.

Session content cannot be deleted

Wait until execution is terminal and publication is no longer in progress. If filesystem cleanup fails, retry deletion. The durable purge marker makes retained content unavailable even while cleanup needs attention.

The server cannot start

Check the data-directory permissions and database compatibility. If port 8765 is occupied, choose another with --port and update the GitHub App callback accordingly. Keep the server loopback-only.
