Documentation / Implementation sessions

Implementation sessions

Run Claude Code against an isolated repository copy and review its recorded work.

Prepare Docker and Claude Code

Start Docker, install and log into the Claude Code CLI (claude), and run the app with --data-dir. Pull your execution image before starting a session. Sessions never pull images and have no container network. For a Python project, one example is:

docker pull python:3.12-slim

Choose an image that already contains your project’s required tools and dependencies; installs that need the network cannot run inside a session.

Create an execution profile

  1. In Settings → Privacy, turn off Keep everything on this computer. The coding agent sends the plan and permitted source to Anthropic.
  2. In Settings → Coding agent, set Pull request author using your own commit identity.
  3. Create a profile with your locally available container image. The optional Claude model accepts an alias or ID; leave it blank to use your Claude Code default. This is separate from Ask’s model.
  4. Enable Allow sending repository source to the external coding model and run Test execution profile until it passes.

The profile version, including its chosen model and limits, is pinned when a session starts. Editing defaults does not change a running session.

Start and supervise

Enable both repository switches, generate a ready plan and select Start session. Follow activity, file changes, the diff and validation results. Send guidance within the recorded scope; follow-ups cannot grant new repository access. Passed, failed and not-run checks are different outcomes. Completion alone does not mean every check passed.

Understand the boundary

The repository copy and commands live in a container with --network none, dropped capabilities, a read-only root filesystem and resource limits. Claude Code runs on the host in an empty private temporary directory, with built-in tools, hooks, plugins, settings, memory and slash commands disabled. It acts through brokered tools into the container and uses your own login to contact Anthropic. Read the security model.

Stop, retry and recover

Stop session blocks new tools and requests termination. Wait for confirmed containment; a containment failure must be treated as unresolved. After an app interruption, startup checks that the old agent and container are gone and marks the session interrupted. Edits after the last checkpoint may be lost. Retry as a new attempt creates linked history; it does not resume an invisible live process.

Delete retained session content

For a finished session, Delete session content purges local events, guidance, diffs, checkpoints and validation output. Minimal identity, base commit and PR linkage remain. An in-progress publication blocks purge. Plans and repository indexes have separate retention controls; GitHub PRs and backups are unaffected.
