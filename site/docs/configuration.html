Configuration and data

Choose persistent storage explicitly and keep the server on loopback.

Command-line options

OptionBehavior and default
--data-dir PATHPersist workspace state here. Omitted: in-memory demo. There is no default persistent directory.
--port NUMBERWeb app loopback port; default 8765.
--model NAMELocal Ollama model for unassigned Ask/planning roles; omitted: no CLI-seeded model.
--ollama-url URLOllama address; default http://127.0.0.1:11434, or OPENDEVENGINE_OLLAMA_URL when set. Use an IP address, not a host name. That IP counts as local. See Ollama on another machine.
--repo NAME=PATHIndex an explicit local checkout at HEAD; repeat up to eight times. Omitted: bundled sample sources.

Check your installed version with python3 -m opendevengine --help. There is no host-binding option: the server binds to 127.0.0.1. No environment variables are needed for the setup in this manual; OPENDEVENGINE_OLLAMA_URL is the optional environment form of --ollama-url, and the flag wins when both are set.

What is stored

The selected data directory holds opendevengine.sqlite3, with SQLite WAL sidecars during use. Persistent records include conversations, immutable plan versions, indexed source, settings and session artifacts. Treat this directory as private source-bearing data. Credentials themselves are in the OS vault, referenced by ID.

The current implementation stores session artifacts in SQLite. Runtime/session-owned files may also exist below the data directory. Session purge removes retained content from active records; it does not erase backups or remove independent plans and repository indexes.

Settings in the app

Use Settings for GitHub, provider profiles and model roles, privacy, coding-agent execution profiles and the pull request author. Use Repositories to control reading and changes separately. Settings that affect a new plan or session do not rewrite its historical version.

Keep persistent data outside the repositories you index. Do not use a development build against a data directory containing credentials you care about. See security before sharing diagnostics or backups.
