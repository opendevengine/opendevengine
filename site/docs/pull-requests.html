Documentation / Pull requests

Pull requests

Publication is a separate, explicit step after implementation.

Review before publishing

Publication is manual by default. Automatic draft publication requires an explicit success-only policy saved with the plan.

  1. Open the finished session’s PR tab and choose Create draft PR.
  2. Review repository, base and head branches, changed paths, omitted files and checks.
  3. Edit the proposed title and description.
  4. Choose Publish draft PR.

The title defaults to the saved plan goal. The description includes plan steps, recorded checks, omitted generated paths and limitations. Inspect the actual diff and checks; a model’s summary is not validation.

What leaves your computer

The publisher sends eligible changed file contents and deletions, a commit with your configured author identity, a new branch, and the PR title and description to GitHub. Publication uses the recorded checkpoint, not a patch reconstructed from model text. The default description excludes source contents, patches and validation output.

Only new opendevengine/… branches and draft PRs are created. The app never merges or pushes to a default branch. Allow changes must still be on.

Omitted and blocked paths

Newly added generated artifacts, such as __pycache__/, are omitted and listed in the preview and default description. Other rejected paths block publication, including modified or deleted tracked files matching generated patterns. Sensitive content, missing artifacts or changed permissions can also block it.

Checks and branch freshness

Manual publication can disclose failed or unavailable checks. A success-only automatic publication policy additionally requires passed required validation and a reviewable completed outcome. Review publication intent in the saved plan; a follow-up message cannot change the frozen policy.

If the base moved, overlapping or incompletely known changes can block publication. The app does not silently rebase.

Retry without duplicating

If a GitHub response is lost, the app reconciles recorded branch and PR state on restart or Retry. Retry continues the same publication intent rather than rerunning implementation or creating a second PR. Deleting local session content does not delete a published PR.
