Documentation / Repository indexing

Repository indexing

Answers refer to committed snapshots, not a live view of uncommitted working files.

Select source

Enable Use in Ask on Repositories. Open a repository’s details to inspect its index and use Index now or Reindex now. Active runs offer Pause or Resume where applicable. Review coverage and skipped-file information before treating the index as complete.

The default index size cap is 4 GiB, measured by live database pages; deleting a local index frees headroom. Indexing also pauses before the data volume would drop below 1 GB free. See Indexing paused: disk limit for recovery steps.

Snapshots and citations

GitHub source is acquired through bounded tree/blob API reads and stored in SQLite. Explicit local checkouts are read at committed HEAD. Indexing never installs dependencies or runs repository scripts. Credential-like files, binary files, symlinks and generated artifacts are excluded before indexing and model calls.

A new index activates as a new snapshot. A failed replacement keeps the previous active context available. An old citation resolves to its recorded snapshot while that source remains available; it does not silently follow the latest branch.

Lexical and semantic search

Full-text search handles literal identifiers. An embedding-capable profile adds semantic retrieval. Without embeddings, lexical-only context remains usable. Changing embedding identity requires a compatible index namespace; incompatible vectors are not mixed.

Partial, stale and unavailable source

Bounded indexing can leave partial coverage. Check repository status and skipped reasons, and reindex after changes. Permission revocation, exclusions and purge can make previously cited source unavailable. Retention does not override access policy.

See asking and planning for how scope and source freshness affect a plan.
