FAQ and limitations

Current scope of the early 0.1 release, with planned work kept separate.

Is everything local?

Storage is local and inference is local by default. Hosted providers require consent. Implementation uses Claude Code on the host and sends permitted source and the plan to Anthropic, while repository tools run in a network-disabled container.

Can I reuse my GitHub CLI login?

No. Connect a GitHub App through Settings. Claude Code uses its own existing login for inference.

Can I use another coding agent?

Claude Code is the only implementation adapter in this release. Ollama and compatible endpoints serve model roles; a chat endpoint alone cannot run an implementation session. A Codex CLI adapter is planned for M4.

Can one session change multiple repositories?

No. A session has one writable repository. Plans can describe broader work, but unsupported multi-write scope blocks launch. Richer cross-repository execution is planned for M4.

Does indexing include all history and local edits?

No. The app uses committed snapshots, not uncommitted files or all Git history. Index limits and exclusions can produce partial coverage. Inspect the citation’s recorded commit and the index status.

Does the app merge or deploy?

No. It publishes draft PRs under the recorded publication policy. You review them on GitHub. It never merges or pushes to a default branch.

Where are skills, plugins and memory?

User-managed skills, approved plugins/MCP tools and scoped memory are planned for M3 and are not built. The current adapter disables Claude Code’s own hooks, plugins, memory and slash commands.

What else should I know?

This is an early release for one user on one computer, without network-facing authentication. CPU-only local models may be slow. Sessions need Docker, a prepared image and a logged-in Claude Code CLI. Deleting local session content does not delete GitHub PRs or backups. There are no performance guarantees in this manual.
