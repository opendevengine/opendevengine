Asking and planning

Find the relevant code, inspect the evidence, then save a plan before starting execution.

Choose the repository

Name a repository in your question or attach it with +. When routing cannot choose, Ask requests a repository choice and shows matching terms for its suggestions. The waiting question and choice survive reloads and restarts in persistent mode.

Inspect citations

Answers cite files and line ranges from indexed commits. Open a citation to see the recorded source, and check index freshness and coverage. Ask reads and calls your configured models; it never runs repository commands or edits files. Model output still needs your review.

Generate and edit a plan

  1. Describe the intended change with the target repository attached.
  2. Choose Generate plan.
  3. Inspect the findings, scope, changes, validation commands, risks and unanswered questions.
  4. Use Edit plan to make changes, then Save immutable version.

Versions retain their source snapshots and content hashes. Starting a session uses the chosen version, not a silently updated plan.

Make it ready to start

A launch needs one writable GitHub repository, usable source, current permissions, no blocking questions and a tested execution profile. With exactly one tested profile, new plans use it. With several, choose one under Edit plan → Execution and publication and save a new version.

If the base branch advanced, choose deliberately between retaining the saved base and regenerating the plan. A saved-base acknowledgement does not rebase the code. Multi-repository planning does not enable multi-repository writes.
